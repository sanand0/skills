# Anand's Skills

Choose skills by their descriptions; read `./{name}/SKILL.md` when relevant.

- agent-friendly-cli: Use when writing command-line scripts agents will control
- anand-laptops: Locate and use Anand's files, projects, notes, archives and agent history on his laptops - graphene (Linux) and Plutonium (Windows, usually online) - which share one ~/ layout. Use before reading or searching his files via LocalMCP2, Remote Desktop Commander or a local shell.
- anand-objectives: Apply to any substantive answer for Anand - strategy, design, build, analysis, teaching, writing, research - to steer it toward his goals (compounding assets, durable skills, the surprising read). Skip for trivial lookups, mechanical edits, focused tasks. Shapes HOW to answer, never overrides WHAT was asked.
- anand-writing-style: To write in Anand's style for blog posts, emails, talk summaries, interview questions, conversations, ...
- blind-spot: Use when value may hide in what's NOT said, asked, measured, tested, shown, or decided - or in what a filter removed: strategy, advisory/sales calls, reviews, data analysis, design, demos, AI outputs, decisions, picks from many (bids, hires, variants), transcript post-mortems. Skip for lookups, mechanical edits, tightly scoped execution.
- code: ALWAYS follow this style when writing Python / JavaScript / HTML / CSS code
- data-analysis: Use to investigate data for surprising, actionable insights
- data-story: Write data findings as a compelling narrative story, Malcolm Gladwell prose, NYT graphics-team visuals, engaging & memorable even for a non-technical audience.
- data-viz: To select, design, annotate, and verify a data visualization (chart, map, or table).
- decision-compression: Automatically compress broad answers into the decision, recommendation, rationale, tradeoff, and next action. Use for recommendations, prioritization, research synthesis, strategy, planning, reviews, rankings, and large-context requests.
- design: ALWAYS follow this design guide for any front-end work
- devtools: Use CDP at localhost:9222 to test/debug websites, automate browser tasks, and inspect/replay browser APIs
- evidence-provenance: Automatically improve trust, auditability, and reuse by separating facts, assumptions, inferences, sources, confidence, and verification. Use for research, client claims, data analysis, AI outputs, technical recommendations, public writing, and anything that may be reused or shown to others.
- expert-lens: Use when domain expertise will significantly change the criteria, recommendations, risks. Skip for routine analysis, mechanical work, etc.
- failure-redteam: Automatically stress-test plans, demos, claims, workflows, AI systems, code, data analyses, assessments, and recommendations by identifying likely failures, misuse, misunderstanding, edge cases, incentives, security/privacy risks, and lightweight mitigations.
- generate-fake-data: Use when creating REALISTIC synthetic data leading to actionable business hypotheses.
- ideation-protocol: Brainstorm creative, novel, non-obvious ideas or options for an open-ended problem and narrow them to a recommendation. Not for writing prose, research, explanation, summaries, or questions with one right answer.
- interactions: Use to create tooltips, popups, interactions, and animations as informative and engaging aids.
- interactive-storytelling: Use interactivity purposefully in data visualizations and narrative content. Trigger for scrollytelling, explorable explanations, simulations, guess-then-reveal patterns, or any data story where user action shapes understanding. NOT for dashboard drill-downs or generic UI interactivity.
- interface-cheat-sheet: A list of tips, improvements and best practices that quickly make your interfaces better.
- llm: For niche models (e.g. OpenRouter) and API keys
- meeting-response-style: Summarize into something I can just read out in a meeting: Minto pyramid structure, answer-first, bolded for scanning, conversational.
- memorable-explanations: Use to intuitively, memorably explain abstract, complex, unfamiliar concepts. NOT for code generation, data retrieval, or when user just needs execution.
- mental-models: Apply relevant mental models for strategy, forecasts, recommendations, or advice. Skip for execution, lookups, and mechanical edits.
- pdf: How to read, manipulate, and generate PDFs using CLI tools and Python libraries.
- possibility-scan: Use when the chosen goal, audience, scale, or approach may hide better opportunities; when new capabilities or setup changes could unlock disproportionate value; or when surprising outcomes merit reframing. Skip routine execution.
- post-mortem: Run when the task reveals a costly, recurring, or likely-generalizable failure, inefficiency, or misalignment. Skip one-offs and complexity alone.
- reframe-question: The user's question may be a DRAFT of their real need. For substantive requests, check if a better question changes what's solved and serves them better. If so, reframe, explain why (in 1 line), THEN answer. Most questions need no reframe; skip precise, mechanical, tightly specified, or already-sharp requests and simply answer.
- stability-check: Use when a factual conclusion, quantitative analysis, evaluation, ranking, benchmark, forecast, or recommendation could change under reasonable choices of definition, scope, inclusion, weighting, model, threshold, source set, or time window. Skip creative work and pure preference questions.
- verification-gate: Run this by default as the final step after any non-trivial workflow - analysis, code, data work, a plan, a factual answer, a deliverable - before presenting it, even when not explicitly asked to verify. Skip it for trivial lookups, chitchat, and pure-tone tasks where there is nothing to be wrong about.
